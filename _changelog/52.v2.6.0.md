## 2.6.0

### November 17, 2026

### &nbsp;&nbsp;&nbsp;✨ Highlights

- **Input prop types are actually checked** 🔍 — a single known `type` now type-checks against its own props in TSX, `h()` and React. `<FormKit type="datepicker" disabledDays="yes" />`, `mask={5}` or `submitBehavior="nope"` used to compile silently; now they're errors. (#1818)
- **Typed event props** — `onInput`, `onInputRaw` and `onUpdate:modelValue` receive the input's value type instead of `unknown`, so `onInput={(value: number | undefined) => …}` compiles and unannotated handlers get a contextual type.

### &nbsp;&nbsp;&nbsp;🧩 Type changes

Runtime is unchanged. TypeScript projects may see new errors where a prop had the wrong type all along — fix the value, or cast. Not changed: required props (like `mask` or a transferlist's `options`) are still optional at the type level, so wrappers that forward `$attrs` or optional props keep compiling; enforcing them waits for the next major. Event-prop values include `undefined` (matching `emit`), so annotate handlers as `(value: string | undefined) => …`.
