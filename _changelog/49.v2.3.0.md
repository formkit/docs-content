## 2.3.0

### November 5, 2026

### &nbsp;&nbsp;&nbsp;✨ Highlights

- **`describeForm()`** (`@formkit/addons`): a JSON snapshot of any form — fields, labels, rules, options, validity and errors — for AI agents, generated tests and debugging. Values are opt-in; `password` and `hidden` inputs are always redacted. [Docs](https://formkit.com/plugins/describe-form)
- **Section refs** (Vue + React): every section's DOM element by key on `node.context.refs` — Vue: `formkitRef.value.refs.input.focus()`, React: `nodeRef.current.context.refs.input.focus()`. [Docs](https://formkit.com/essentials/inputs#section-refs)
- **Faster mounts**: large forms mount ~10% faster (450 inputs: 412 → 369 ms).
- **vue-tsc**: `<FormKit>` prop and slot types work in SFC templates again (#1777).
- **Nuxt**: common FormKit types (`FormKitNode`, `FormKitConfig`, …) are auto-imported in every mode.

### &nbsp;&nbsp;&nbsp;⚠️ Behavior notes

- A **group/list** `<FormKit>` (e.g. `type="form"`) no longer emits `input`/`inputRaw` when nothing listens. Apps can't observe this; it only shows up in `@vue/test-utils`' `wrapper.emitted()` on a bare group with no listener. Plain inputs are unchanged.
- Nuxt: if your app defines its own type with one of the auto-imported names in `composables/` or `utils/`, Nuxt may log a duplicated-import warning; your local declaration still wins in that file.

### &nbsp;&nbsp;&nbsp;⚠️ Type changes

`<FormKit>`'s public type is now *only* its generic call signature, which is what lets `vue-tsc` infer props and slots in templates again (#1777). That means:

- **Templates that compiled before may now show real type errors** in `vue-tsc` (they were silently `any` since 2.0). These are genuine prop/slot mistakes being caught.
- A few TypeScript patterns that relied on `<FormKit>` being a `DefineComponent` no longer type-check. For all of them, use **`FormKitRuntimeComponent`** (also exported from `@formkit/vue`), which is the same component typed as a `DefineComponent`:

| Pattern | Before | Now |
|---|---|---|
| `InstanceType<typeof FormKit>` / `ref<InstanceType<typeof FormKit>>()` | ✅ | ❌ TS2344 → `InstanceType<typeof FormKitRuntimeComponent>` |
| `h(FormKit, { type: 'text', label: 'x' })` (no `as const`) | ✅ | ❌ TS2769 → add `as const`, or `h(FormKitRuntimeComponent, …)` |
| `h(FormKit, props)` with `props: Record<string, any>` (spread / config-driven) | ✅ | ❌ TS2769 → `h(FormKitRuntimeComponent, props)` |
| `h(FormKit, { type: t })` with `t: string` (dynamic / schema-driven type) | ✅ | ❌ TS2769 → `h(FormKitRuntimeComponent, …)` |
| `const c: DefineComponent<any> = FormKit` | ✅ | ❌ TS2322 → `FormKitRuntimeComponent` |
| `(typeof FormKit)['props']` | ✅ | ❌ TS2339 → `(typeof FormKitRuntimeComponent)['props']` |
| `defineComponent({ extends: FormKit })` | ✅ | ❌ TS2769 → `extends: FormKitRuntimeComponent` |

Unchanged: `components: { FormKit }`, `app.component('FormKit', FormKit)`, `const c: Component = FormKit`, `h(FormKit)`, `h(FormKit, {...} as const, slots)`, and TSX `<FormKit type="text" />`. Runtime behavior is identical.
